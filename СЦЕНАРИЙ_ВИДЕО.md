# Сценарий видео по неделям (3–5 минут на неделю)

Общий порядок: открыть `.pbix` → показать модель → показать отчёт и щёлкнуть срезы → коротко ответить на 2–3 вопроса защиты. Цифры для голоса — в таблицах ниже, подробности — в `Отчёт_НеделяN.docx`.

Перед записью: если путь к Excel на компьютере другой, поменять параметр `pSourceFile` (недели 2, 4, 5, 6) или `pFolderPath` и `pReferenceFile` (неделя 3) через «Преобразовать данные → Изменить параметры». Неделя 1: «Настройки источника данных».

## Неделя 1 — первый отчёт
1. «Справка → О программе» — версия.
2. Power Query: таблица Sales, типы (Order Quantity — целое, Unit Price и Sales Amount — десятичные).
3. Model View: «Sales — факт, вокруг 4 измерения, связи один-ко-многим. Связь по дате я сделал вручную: OrderDateKey → DateKey».
4. Страница Sales Overview: Total Sales 109,8 млн → в срезе выбрать Bikes → 94,6 млн, «все визуалы отфильтровались».
5. Grain: «одна строка Sales — один товар в заказе».

## Неделя 2 — Power Query ETL
1. stg_Sales с включённым профилированием: шаг до очистки — 68 городов, последний шаг — 16. Строк 338 → 320 (18 полных дубликатов).
2. Пройтись по Applied Steps: Trim/Clean/Proper → маркеры N/A, «-», error → null → проценты «10%» в число → даты из 3 форматов → удаление дубликатов.
3. FactSales — Reference: «цену беру из прайса, сумму, количество и скидку восстанавливаю по формуле Q × P × (1 − D), регион — из справочника по городу».
4. Fill Down в stg_Regions, Split/Merge в stg_Products, Unpivot в SalesMonthly, Group By и Pivot.
5. «Вид → Зависимости запросов»: Source → staging → final.
6. Воспроизводимость: «добавил 5 грязных строк, обновил — стало 325, всё почистилось само».

## Неделя 4 — Star Schema
1. Model View: FactSales в центре, 5 измерений, все связи 1:* и Single, ID скрыты.
2. Grain: «одна строка = позиция заказа, OrderID повторяется — в заказе несколько товаров, PK — SalesLineID».
3. Ловушки: ProBook у двух ProductID, у 19 имён клиентов несколько CustomerID.
4. Страница «Проверка модели»: срезы Категория, Регион клиента, Регион магазина меняют цифры.
5. Страница «Аудит ключей»: PK 12/12, 120/120… и FK без пары — 0.

## Неделя 5 — связи
1. Model View: два факта на общих измерениях, без связи факт–факт. Пунктир — ShipDate (неактивная).
2. Мера Sales by Ship Date с USERELATIONSHIP, график по месяцам: «в августе 2026 по отгрузке на 11,8 млн больше».
3. 1:1 DimStore–DimStoreDetails. Мост товар–акция: в New Year Tech 6 товаров, AeroBook 14 в двух акциях.
4. Single против Both: срез Mouse Air → клиентов 100 (Single) и 69 (Both). «Both включал только как эксперимент, вернул обратно».
5. Бюджет: «сравниваю только по магазину, категории и месяцу. По товару нельзя — в бюджете нет товаров».

## Неделя 6 — DAX
1. Таблица _Measures с 5 папками, 23 меры.
2. Orders Count 820 против Sales Lines 1577 — «строка = позиция, а не заказ». Средний чек 1,17 млн против средней строки 0,61 млн.
3. Filter Context: срезы Year, Brand, Segment — одна мера 957 → 558 → 324 → 83 млн.
4. SUMX: Sales Recalculated = Total Sales. На трёх строках показать Q × P × (1 − D) вручную.
5. VAR в Profit Margin % и Sales YoY % (+11,9 %), IF Sales Status, SWITCH Performance Level (аксессуары — A, ноутбуки — B).
6. «Profit Row Calc как столбец я сделал и скрыл: он дублирует ProfitAmount, а итог должна считать мера».
